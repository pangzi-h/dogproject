# PRD: 订单管理系统

**模块编号**: MOD-004  
**优先级**: P0  
**所属版本**: MVP v1.0

## 一、模块概述

### 业务背景
- 订单是支撑整个业务的核心
- 订单管理不仅包括用户端查看，还包括内部运营、寄养人分配、时间表等
- 需要清晰的订单状态流转

### 核心功能
- 用户订单查看与管理
- 订单状态追踪
- 订单取消与退款
- 运营后台订单管理

## 二、用户故事

### 用户故事 1: 查看订单历史
```
作为一个平台用户
我想查看我之前所有的寄养订单
这样我可以快速下次预订或查看往期反馈

验收标准:
✓ 显示所有历史订单 (已完成+已取消)
✓ 按时间倒序排列
✓ 快速重复预订按钮
```

### 用户故事 2: 取消订单
```
作为一个需要取消的用户
我想快速取消订单并获得退款
还要清楚了解退款政策

验收标准:
✓ 订单支付成功后可在 24 小时内全额退款
✓ 寄养开始后可申请退款但需审批
✓ 退款周期清晰 (1-3 个工作日)
```

### 用户故事 3: 快速重复预订
```
作为一个老用户
我想基于上次的订单快速预订
比如选same_pet、same_service_type

验收标准:
✓ 一键快速预订相同配置
✓ 可修改日期和时长
✓ 预设价格建议
```

### 3.3 用户端-取消订单

#### 取消申请流程

```
点击 [申请取消]
  ↓
系统检查订单状态
  ├─ 待支付 → 直接取消，返回库存
  │
  ├─ 已支付且寄养未开始 (< 24 小时) → 全额退款
  │   ↓
  │   显示: "可在 24 小时内全额退款"
  │   显示: "原支付账户在 1-3 个工作日到账"
  │
  ├─ 已支付且寄养开始 → 需申请审批
  │   ↓
  │   显示: "寄养已开始，取消需要寄养人确认"
  │   提示: "可能产生服务费"
  │   输入: 取消原因 (选择 or 自由文本)
  │   按钮: [申请取消] / [保持预订]
  │
  └─ 已完成/已取消 → 无法操作
```

### 3.4 快速重复预订

#### 触发位置
- 已完成订单卡片的 [再次预订] 按钮
- 订单详情页的 [快速预订] 按钮
- 用户首页的 "推荐下次预订" 卡片

#### 流程

```
用户点击 [再次预订]
  ↓
自动进入预订 Step 1，预填:
  • 同一只宠物 (已选中)
  • 建议套餐: 上次服务类型
  • 建议时长: 上次时长
  • 建议日期: 下周同周几或用户可选
  ↓
展示: "基于您上次预订的经历"
  • 时长建议: "上次订了 5 天"
  • 套餐建议: "您上次选的是标准寄养"
  • 价格预览: "预计 ¥440"
  ↓
用户可修改任何字段后继续流程
  ↓
进入 Step 2 (阿选择套餐) 跳过
  ↓
进入 Step 3 (选择宠物) 预选，可修改
  ↓
进入 Step 4 (确认支付) 
```

## 四、订单状态机

```
待支付
  ├─ (支付成功) → 已支付
  └─ (支付失败/超时) → 已取消

已支付
  ├─ (寄养日期到) → 寄养中
  └─ (用户取消) → 退款中

寄养中
  ├─ (到出院时间) → 待取货
  └─ (用户申请取消) → [人工审批] → 退款中 / 继续中

待取货
  ├─ (用户取货/派送) → 已完成
  └─ (超过 7 天未取货) → 逾期寄存

已完成
  └─ (用户评价) → 可生成满意度反馈

退款中
  ├─ (退款成功) → 已退款
  └─ (退款失败) → 退款失败

其他: 已取消, 已退款, 逾期寄存
```
