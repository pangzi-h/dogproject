# PRD: 每日反馈系统

**模块编号**: MOD-003  
**优先级**: P0 (核心)  
**所属版本**: MVP v1.0

---

## 一、模块概述

### 业务背景
- 用户最关心: "我的宠物在你这里过得怎样？"
- 每日反馈是信任建立和差异化的关键
- 反馈频率和质量直接影响复购率

### 竞品对标

| 竞品 | 反馈形式 | 频率 | 用户体验 | 差异 |
|------|---------|------|---------|------|
| **58宠物** | 无反馈 | - | 信任度0 | 完全不解决用户需求 |
| **宠那么萌** | 文字+1-2张图 | 1次/天 | 信息量少 | 用户体验一般 |
| **宠幸** | 视频片段+文字 | 2-3次/天 | 信息丰富 | 操作复杂，需要很多设备 |
| **我们的优势** | **精准反馈模板** | **1-2次/天** | **简洁高效** | **寄养人零学习成本** |

## 二、用户故事

### 用户故事 1: 查看每日反馈
```
作为一个寄养中的宠物主人
我想每天能看到我的宠物在基地的活动情况
这样我在外面工作才能放心

验收标准:
✓ 每日至少1次反馈
✓ 反馈包含活动内容、进食状况、排便时间
✓ 反馈有照片或视频
✓ 反馈通知及时推送
✓ 点开通知立即显示最新反馈
```

### 用户故事 2: 不同套餐看反馈频率
```
作为一个不同套餐的用户
我想看到与套餐相符的反馈频率
这样可以明确期望值

验收标准:
✓ 基础: 1 次/天 (纯文字)
✓ 标准: 1-2 次/天 (文字+图片)
✓ VIP: 2-3 次/天 (文字+图+视频)
```

### 用户故事 3: 快速反馈(寄养人)
```
作为一个寄养人员
我想快速填写每日反馈不要太复杂
这样我可以在日常工作中花最少时间

验收标准:
✓ 反馈表单 < 2 分钟完成
✓ 预设选项而不是自由文本
✓ 一键上传照片
```

## 四、用户推送与通知

### 推送时机

```
1️⃣ 反馈发布时推送
   标题: "小黑 有新的每日反馈"
   内容: "今天表现很好！点击查看详情"
   时间: 反馈发布后 5 秒内
   
2️⃣ 提醒用户迟到反馈 (仅内部)
   给寄养人: "小黑 的反馈已迟到 1 小时"
   优先级: P1 (高)
```

### 通知文案

```
标准套餐 (1 次/天):
   "小黑 有新的每日反馈 📸"
   "进食正常 ✓ | 情绪开心 😊 | 排便正常 ✓"

VIP 套餐 (2-3 次/天):
   "小黑 有新的视频直播 🎥"
   "在草坪上开心地与小伙伴们奔跑！"
```

## 五、反馈质量控制

### 反馈审核机制

```
1️⃣ 自动检查 (发布时)
   ✓ 照片数 ≥ 1
   ✓ 活动至少选 3 项
   ✓ 进食、排便必填
   → 满足条件: 自动通过
   → 不满足: 提示填写

2️⃣ 管理员抽查 (20%)
   每天抽查 20% 的反馈
   检查项:
   • 照片是否真实 (确实是该宠物)
   • 备注是否真实可信
   → 发现虚假: 删除+警告
   → 情况严重: 下线寄养人
```

### 反馈质量评分系统

```
系统自动计算反馈质量分:

维度 1: 完整性 (0-30 分)
  • 照片 > 2 张: +10 分
  • 活动 > 4 项: +10 分
  • 备注 > 50 字: +10 分

维度 2: 及时性 (0-30 分)
  • 当天发布: +30 分
  • 次日发布: +15 分
  • 延迟 2+ 天: 0 分

维度 3: 用户反馈 (0-40 分)
  • 用户点赞: +5 分/次
  • 用户评论: +3 分/条
  • 用户反感: -5 分/次

总分 = 完整性+及时性+用户反馈

优秀反馈 (≥ 80 分):
  列入平台展示
  寄养人排名靠前
```

## 六、数据模型

### daily_feedbacks 表
```sql
CREATE TABLE daily_feedbacks (
  id CHAR(36) PRIMARY KEY,
  order_id CHAR(36) NOT NULL,
  pet_id CHAR(36) NOT NULL,
  user_id CHAR(36) NOT NULL,
  caretaker_id CHAR(36) NOT NULL,
  
  feedback_date DATE NOT NULL,
  feedback_day_number INT COMMENT '寄养第几天',
  
  -- 内容
  activities JSON COMMENT '["早晨散步", "室内游戏", ...]',
  breakfast_status ENUM('正常','偏少','拒食'),
  lunch_status ENUM('正常','偏少','拒食'),
  dinner_status ENUM('正常','偏少','拒食'),
  water_intake ENUM('正常','偏少','过多'),
  bowel_status ENUM('正常','偏干','偏软','腹泻'),
  bowel_times INT,
  mood ENUM('非常开心','正常','情绪低落','焦虑'),
  notes TEXT,
  
  -- 媒体
  photo_count INT DEFAULT 0,
  photo_urls JSON COMMENT 'OSS 图片 URL 数组',
  video_url VARCHAR(500) COMMENT 'VIP 专享视频 URL',
  video_duration INT COMMENT '视频秒数',
  
  -- 质量评分
  quality_score INT DEFAULT 0,
  is_featured BOOLEAN DEFAULT FALSE COMMENT '是否在平台展示',
  audit_status ENUM('待审核','已通过','驳回'),
  
  feedback_status ENUM('草稿','已发布','已删除') DEFAULT '草稿',
  
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  published_at TIMESTAMP NULL,
  updated_at TIMESTAMP,
  
  FOREIGN KEY (order_id) REFERENCES orders(id),
  FOREIGN KEY (pet_id) REFERENCES pet_profiles(id),
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (caretaker_id) REFERENCES caretakers(id),
  
  INDEX idx_order_id (order_id),
  INDEX idx_user_id (user_id),
  INDEX idx_feedback_date (feedback_date),
  INDEX idx_quality_score (quality_score)
);
```

### feedback_photos 表
```sql
CREATE TABLE feedback_photos (
  id CHAR(36) PRIMARY KEY,
  feedback_id CHAR(36) NOT NULL,
  photo_url VARCHAR(500) NOT NULL,
  display_order INT DEFAULT 0,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (feedback_id) REFERENCES daily_feedbacks(id) ON DELETE CASCADE,
  INDEX idx_feedback_id (feedback_id)
);
```
